# UAT 測試指引（Excel Formula Inspector v1.0.0）

本文件提供**使用者驗收測試（UAT）**所需的測試檔案、預期結果與記錄方式。

所有測試檔案都由程式產生（`src-tauri/examples/make_uat_fixtures.rs`），
**不含任何真實資料**，可自由複製與外流測試。下表的「預期結果」是由**工具的實際解析器與規則引擎**
跑出來的數字，不是人工推測——請以此為驗收基準。

> 全部 9 個檔案都是**有效的工作簿**（UAT-07／UAT-08 例外，它們故意是不支援／損毀的檔案，
> 用來驗證錯誤處理）。沒有任何一個檔案是「佔位檔」。

---

## 1. 取得測試檔案

```bat
make-uat-files.bat                 :: 產生到 <專案>\uat-fixtures
make-uat-files.bat D:\UAT\files    :: 產生到指定資料夾
```

腳本會產生 9 個檔案並在畫面上印出每個檔案的預期結果。要換一份乾淨的副本時重新執行即可。

| 檔案 | 大小 | 用途 |
|---|---|---|
| `UAT-01-clean-monthly-report.xlsx` | 8 KB | 乾淨樣本：不應產生任何問題 |
| `UAT-02-invalid-references.xlsx` | 6 KB | 錯誤值與 `#REF!` 的偵測能力 |
| `UAT-03-pattern-anomaly.xlsx` | 6 KB | F003／F004／F005 三種異常各一 |
| `UAT-04-intentional-breaks.xlsx` | 6 KB | 誤報控制：合併標題、空白列、硬編碼小計 |
| `UAT-05-special-formulas.xlsx` | 6 KB | 不支援語法必須「無法判讀」 |
| `UAT-06-large-sparse.xlsx` | 6 KB | 稀疏工作表（資料在第 100,000 列） |
| `UAT-07-unsupported-legacy.xls` | 12 B | 不支援格式必須被拒絕 |
| `UAT-08-damaged-file.xlsx` | 2 KB | 損毀檔必須被拒絕且不當機 |
| `UAT-09-large-workbook-over-20MB.xlsx` | 22 MB | 大小上限與實驗性模式流程（**有效**的 22.2 MB 工作簿） |

## 2. 建議的 UAT 流程

1. 啟動 `excel-formula-inspector.exe`（或安裝檔安裝後的版本）。
2. 依序匯入 UAT-01 → UAT-09，每個檔案完成第 3–6 步後再按**清除資料**。
3. **摘要**：比對「工作表數、公式儲存格、常數儲存格、錯誤儲存格、問題總數」與下表。
4. **問題清單**：比對問題筆數、規則 ID 與儲存格位址；點選一筆，確認右側有「判斷依據」與
   相鄰公式比較，且啟發式結果標示為「疑似」並附信心程度。
5. **公式檢視**：用位址跳轉與關鍵字搜尋，確認公式原文、快取值、直接參照與同欄主流簽章正確。
6. **工作表網格**：確認可捲動到已使用範圍邊界（UAT-06 請跳到第 100,000 列），有問題的儲存格有 ⚑ 標記。
7. **匯出**：以 CSV 匯出目前篩選結果，用 Excel 開啟確認中文正常、欄位完整；再用 JSON 匯出一次。
8. 記錄結果（見第 5 節表格）。

## 3. 各檔案的預期結果

### UAT-01-clean-monthly-report.xlsx
內容：3 個工作表（`Inputs`、`Monthly Report`、`Summary`）、39 個公式，包含 SUM／IF／VLOOKUP／
XLOOKUP／AVERAGE／ROUND／TEXT、相對與絕對參照、跨工作表參照與一個合併的標題列。

| 指標 | 預期 |
|---|---|
| 工作表數 | 3 |
| 公式儲存格 | 39（Inputs 10、Monthly Report 25、Summary 4） |
| 常數儲存格 | 52 |
| 錯誤儲存格 | 0 |
| **問題總數** | **0** |

驗收重點：**乾淨的工作簿不得產生任何問題**（沒有誤報）。若出現問題，請記錄規則 ID 與儲存格。

---

### UAT-02-invalid-references.xlsx
內容：5 個公式，含刪除欄造成的 `#REF!`、`=1/0` 的 `#DIV/0!`、查不到的 `#N/A`，
以及兩個**陷阱**：公式中的字串常值 `"#REF! is just text"`、以及純文字儲存格 `#REF!`。

| 指標 | 預期 |
|---|---|
| 問題總數 | **4** |
| F001 錯誤值（High） | 3 筆：`Errors!B2`、`Errors!B3`、`Errors!B4` |
| F002 無效參照（High） | 1 筆：`Errors!B2` |
| F003 / F004 / F005 / F006 | 0 筆 |

驗收重點：
- `Errors!B5`（字串常值）與 `Errors!B6`（純文字）**不得**產生 F002。
- F001 的證據需包含錯誤類別與「快取錯誤值可能與目前計算結果不一致」的提示。

---

### UAT-03-pattern-anomaly.xlsx
內容：`Patterns` 工作表，三種異常各一。

| 指標 | 預期 |
|---|---|
| 問題總數 | **3** |
| F003 公式模式不一致（Medium） | 1 筆：`Patterns!B7` |
| F004 疑似硬編碼覆寫（Medium） | 1 筆：`Patterns!C5`（值 `999`） |
| F005 疑似公式缺口（Low） | 1 筆：`Patterns!D5` |

驗收重點：
- F003 的證據要顯示「主流簽章 … 筆數 x/y」與本儲存格的簽章。
- F004／F005 的訊息與證據必須使用「疑似」，並提示可能是小計／輸入欄／刻意留白。
- 這三筆的嚴重度與信心程度需與上表一致（F003 可能為 medium 或 high，依主流佔比決定）。

---

### UAT-04-intentional-breaks.xlsx
內容：`Report` 工作表，含**合併的標題列**、**完全空白列**、一個**硬編碼小計**（`C12 = 60000`）。

| 指標 | 預期 |
|---|---|
| 問題總數 | **1** |
| F004 疑似硬編碼覆寫（Medium） | 1 筆：`Report!C12` |
| F003 / F005 | **0 筆** |

驗收重點：
- 合併標題列與完全空白列**不得**產生任何問題。
- 硬編碼小計**應該**被標記（附「可能是合法的小計」提示），這是預期行為而非誤報。
- F005 不得跨越完全空白列推定。

---

### UAT-05-special-formulas.xlsx
內容：`Special` 工作表，含結構化參照 `Table1[Amount]`、外部活頁簿 `'[Budget 2024.xlsx]Sheet1'!A1`、
3D 參照 `Sheet1:Sheet3!A1`、溢出運算子 `A2#`，以及 `LAMBDA`。

| 指標 | 預期 |
|---|---|
| 問題總數 | **0** |
| F003 / F001 / F002 | **0 筆** |

驗收重點：
- 這四種不支援語法在**公式檢視**與**儲存格明細**需顯示「**無法判讀**」（附原因），
  且**不得**被當成異常（不接受把「無法判讀」變成 F003 的行為）。
- `LAMBDA` 為可解析語法，應正常列出參照，不列為無法判讀。

---

### UAT-06-large-sparse.xlsx
內容：`Sparse` 工作表，只有 15 個儲存格，最後一筆在第 100,000 列。

| 指標 | 預期 |
|---|---|
| 已使用範圍 | `A1:D100000` |
| 問題總數 | 0 |
| 掃描耗時 | 應在數秒內（稀疏表不得因虛擬網格變慢） |

驗收重點：工作表網格可捲動／跳轉到第 100,000 列並看到 `Notes` 欄的 `row 99999`。

---

### UAT-07-unsupported-legacy.xls
預期：**明確拒絕**，錯誤代碼 `UNSUPPORTED_FORMAT`，訊息說明 MVP 僅支援 `.xlsx` 與 `.xlsm`。
驗收重點：不出現白畫面、不崩潰，可立即改匯入其他檔案。

---

### UAT-08-damaged-file.xlsx
預期：**明確拒絕**，錯誤代碼 `CORRUPT`，訊息為「檔案損毀或格式不正確，無法解析。」。
驗收重點：訊息不含內部堆疊或完整本機路徑。

---

### UAT-09-large-workbook-over-20MB.xlsx
內容：`Ledger` 工作表，280,022 個儲存格（其中 20 個公式），**是有效的標準工作簿**（Excel 可正常開啟），
檔案大小約 22.2 MB。內含大量互不重複的字串，所以壓縮後仍超過 20 MB 門檻。

| 指標 | 預期 |
|---|---|
| 匯入時 | 先跳出**確認提示**，顯示「檔案大小 22.2 MB 超過預設上限 20 MB」 |
| 選擇「取消」 | 回到可重新匯入的狀態，不得開始掃描 |
| 選擇「以實驗性模式繼續」 | **正常完成掃描**（不是失敗） |
| 工作表數 | 1（`Ledger`） |
| 公式儲存格 | 20 |
| 常數儲存格 | 280,002 |
| 錯誤儲存格 | 0 |
| **問題總數** | **0** |
| 掃描耗時 | 約 2–3 秒（release 建置實測 2.17 秒） |

驗收重點：
- 這是**唯一**會走「實驗性模式」的檔案，確認後必須成功，且在掃描期間畫面可取消、不凍結。
- 掃描完成後「已啟動實驗性模式」的提示**不得**與任何錯誤訊息同時出現。
- 工作表網格可捲動到第 280,001 列。

> 產生器印出的耗時是**除錯（debug）建置**的數字，僅供參考；請以程式畫面「摘要 → 掃描耗時」顯示的
> 正式版數字為準（下方有正式版實測值）。
>
> 若還想測**更大**的檔案（例如公司實際的 50 MB 報表），請自行準備；**請勿使用客戶機密資料**，
> 或先去識別化。若要調整測試檔大小，可修改 `src-tauri/examples/make_uat_fixtures.rs` 中
> `write_large_workbook` 的 `ROWS` 後重新執行 `make-uat-files.bat`。

## 3.1 效能參考（release 建置實測）

同一台開發機、以 `cargo run --release --example make_uat_fixtures` 量測「讀檔＋規則掃描」：

| 測試檔案 | 儲存格數 | 讀檔＋規則耗時 |
|---|---|---|
| UAT-01-clean-monthly-report.xlsx | 91 | 3 ms |
| UAT-02-invalid-references.xlsx | 15 | 1 ms |
| UAT-03-pattern-anomaly.xlsx | 36 | 3 ms |
| UAT-04-intentional-breaks.xlsx | 42 | 2 ms |
| UAT-05-special-formulas.xlsx | 18 | 1 ms |
| UAT-06-large-sparse.xlsx | 15（尾端在第 100,000 列） | 22 ms |
| UAT-09-large-workbook-over-20MB.xlsx | 280,022 | 2,166 ms |

重點：稀疏工作表（UAT-06）不會因為有 10 萬列而變慢；22 MB／28 萬格的大檔約 2 秒完成，
遠低於「大檔可能很慢」的預期。程式畫面顯示的耗時會略高於上表，因為還包含 IPC 傳輸與畫面渲染。

## 4. 已知的非缺陷（請勿回報為 bug）

| 現象 | 說明 |
|---|---|
| 快取值與 Excel 現值不同 | 工具**不會重新計算**公式，顯示的是檔案中既有的快取值，可能已過期 |
| 形狀與上方不同的**公式型合計列**被標為 F003 | 依 SPEC §5／§5.1 的定義，偏離主流簽章的公式本來就會被標記為「疑似」 |
| 不支援語法顯示「無法判讀」 | 依 SPEC §5.1、§13.3 的保守策略，不猜測為錯誤 |
| 無法偵測隱藏列 | `calamine` 未提供列／欄隱藏狀態，因此提示中不含隱藏列 |
| 超過 20,000 筆問題時清單只顯示部分 | 單次 IPC 傳輸上限；統計數字與「匯出全部」仍是完整結果 |
| 檔案遺留在記憶體直到清除 | 按「清除資料」或關閉程式即釋放；不會寫入磁碟或瀏覽器儲存 |
| 22 MB／28 萬格的檔案約需 2–3 秒 | release 實測 2.17 秒，屬預期的實驗性模式成本；一般工作簿（UAT-01～UAT-06）都在毫秒級完成 |
